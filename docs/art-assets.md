# 《妖刀武士》MVP 美术资源清单

> **版本**：1.0 · **日期**：2026-11-23
> **对应 PRD**：`docs/妖刀武士-产品需求文档-PRD.md` v1.0
> **对应技术文档**：`docs/architecture.md` v1.0
> **核心原则**：先占位后替换；MVP 阶段所有正式资源都可由 Phaser Graphics 程序化绘制替代，开发不受阻塞

---

## 0. 两种资源形态的关系

| 阶段 | 资源来源 | 目的 |
|---|---|---|
| **开发期占位符** | Phaser `Graphics` API 程序化绘制（纯色 + 描边 + 几何形状） | 快速搭建可玩 Demo，不依赖美术进度 |
| **正式资源** | 美术外包交付的 PNG / Sprite Sheet / Tile 集 | 替换占位符，最终可部署版本 |

**MVP 交付标准**：占位符即可完成开发。正式资源在 MVP 打磨阶段（Phase 5）逐步替换。

## 10. 资源交付规范（给美术的需求）

正式资源替换时必须满足以下规格（减少返工）：

### 10.1 Sprite Sheet 规格

- **帧尺寸统一**：同一 Sprite Sheet 内所有帧宽度 × 高度相同
- **锚点统一**：角色和怪物的脚底锚点（anchorX = 0.5, anchorY = 1.0）
- **背景透明**：PNG-24 透明通道
- **动作事件帧标注**：
  - 普攻：第几帧攻击生效
  - Q：第几帧开始突进 / 第几帧结束
  - R：第几帧蓄力完成 / 第几帧挥刀生效
  - 敌人攻击：第几帧发射伤害事件
- **循环方式**：idle / walk 循环；attack / death 单次

### 10.2 命名规范

## 11. 占位符 → 正式资源的替换方式

Phaser 的 `PreloadScene` 按 key 加载资源，实体代码只引用 key。替换时**不改业务代码，只换资源文件**：

```typescript
// 占位符（Phase 0–4）：
// 代码内直接用 Phaser.Graphics 生成，不调 PreloadScene
create() {
  const g = this.add.graphics();
  g.fillStyle(0x444444).fillRoundedRect(-20, -30, 40, 60, 8);
  // ... 临时贴图
}

// 正式资源（Phase 5 替换）：
// PreloadScene 加载 'samurai_walk'，实体代码切换为 this.add.sprite(key)
create() {
  this.add.sprite(0, 0, 'samurai_walk');
}
```

**安全网**：可以在 Placeholders 层用 `if (this.textures.exists(key))` 判断正式资源是否已到位，没到位则 fallback 到 Graphics 版本。这样替换可以**逐个替换**，不阻塞任何 Phase。
